DeepSeekMoE 路由 架构图｜专家怎么分，才不挤一个

这段 MoE 建模代码躺在 DeepSeek-VL2 仓库里（官方 V2 的 modeling_deepseek.py 搬过来的）——因为 V2 / DeepSeek-MoE 两个仓库只放了 README 和 PDF。

人话版这段代码躺在 DeepSeek-VL2 的仓库里，是官方 V2 的建模实现——V2 和 DeepSeek-MoE 两个仓库只放了论文和图片，没放代码。它干的事是：把一大坨计算拆成很多个「小专家」，每个词只请其中几个来算，省算力也更懂行。风险是所有词都去找同一个专家，所以训练时要额外扣分：谁被用得太偏，就把分数往回拉。

仓库 deepseek-ai/DeepSeek-VL2 语言 Python 规模 1,975 行 出处 7 处能对到源码 更新 2026-11-04

三个反直觉的地方

  • 把一个大前馈层拆成很多个窄的，每个词只请几个——能拼出来的组合比单个大层多得多，参数涨了，但每个词只付几个专家的算力。
  • 训练时多了一项扣分：统计每个专家被选中的比例和它拿到的平均分数，两者相乘再求和；谁被用得太偏这项就大，梯度会把门往平均那边推。这项只在训练时有。
  • 把词送到专家手里有两套代码：训练时每个词复制 k 份、逐个专家跑；推理时先按专家排序再一次算完，跨卡时用 all_to_all 把词发到有这个专家的机器上。
