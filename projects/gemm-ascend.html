DeepGEMM-Ascend 架构图｜同一套 GEMM，换一套台阶

同样的矩阵乘法，昇腾上数据要依次过 GM→L1→L0→L0C：没有 TMA、没有 cluster，连 scale 的存法都得改。

DeepGEMM-Ascend moves the same matrix multiply onto the Ascend memory hierarchy.

人话版同样是算矩阵乘法，英伟达的卡和华为的卡，数据要走的台阶不一样。这个项目把原来给英伟达写的那套，改成走华为卡自己的台阶：先搬到哪儿、再搬到哪儿、算完从哪儿倒出来。对使用者来说没变：还是同一个函数名、同一套调用方式。

仓库 deepseek-ai/DeepGEMM-Ascend 语言 C++ / Python 规模 19,908 行 出处 8 处能对到源码 更新 2026-11-04

三个反直觉的地方

  • TMA 和 cluster 在昇腾上没有对应物：全仓库搜不到，搬运换成 MTE2/MTE1 两条搬指。
  • shared memory 换成 L1、TMEM 换成 L0C，装不下直接在编译期报错。
  • 连 scale factor 都得改格式：一对 UE8M0 打包成一个 int16，按 MN-major 存。
