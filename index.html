一个命令行小工具：你给它一条规则，它把 JSON 变成你要的样子。
  • 一条规则能吐出好几个结果（比如 .[]），靠的是「存档」：算出一个结果就先记住算到哪了，下次从那儿接着算，不用重头来。

3FS deepseek-ai/3FS 分布式存储C++
DeepSeek 自己造的网盘，训练数据就存在这上面：写得慢一点，读得特别快。
  • 同一份数据存三份，排成一条链。写只找链头，链头一层层往下传；读随便挑一台都行——所以副本越多，读取越快。
  • 「这个文件在哪、多大」这类目录信息不放在自己身上，全丢给一个外部数据库（FoundationDB）。所以每台元数据服务器都是无状态的，挂了换一台接着干。
  • 系统自带的挂载方式（FUSE）太慢，每秒四十万次小读就卡住了。于是它在自己进程里开了条快速通道：应用直接往共享内存里写，网卡直接读走，不复制。

Redis redis/redis 数据库事件循环C
放在内存里的数据库：一个人干活、不用加锁，一条命令眨眼就回来。
  • 一条命令从头到尾只有一个线程在处理，所以不用加锁、也不会互相等。真正的瓶颈是网络来回那一趟（0.1 毫秒），不是算得慢。
  • 只存几个字段的小表，它不当哈希表存，而是塞进一段连续内存里——省地方，也更快，因为一次就能读进 CPU 缓存。字段多了才升级成正经哈希表。
  • 写日志落盘不占主线程：命令先写进内存里的一块缓冲，主线程到点刷给系统，真正落盘交给后台线程。所以开了日志也不会明显变慢。

FlashMLA deepseek-ai/FlashMLA CUDAMLAkernelKV cache
给显卡写的专用程序：算「注意力」这一步，一次吃完 2048 个候选。
  • 一个 GPU 核心里 384 个线程分工：128 个算指数、128 个把压缩过的数据还原、1 个发矩阵指令、1 个搬数据、1 个算地址——像流水线，各干一段。
  • 数据是压缩着存的，用的时候才现算「第几页第几个」把它捞出来：一次搬 4 行，64 行分 16 次搬完；索引越界就填 -1，让硬件自己跳过。
  • 压缩得很狠：512 个数字压成 8 位整数，连位置编码一起压，再配 16 字节缩放系数。一个 token 只占 528 字节；更狠的版本只占 256 字节。

DeepSeek-V3 inference deepseek-ai/DeepSeek-V3 MoEMLA推理
官方推理代码：一个词进来，模型怎么一步步算出下一个词。
  • 128 个头要用的数据其实不用都存：只存 512 个压缩后的数 + 64 个位置数，一共 576 个；老老实实存要 32768 个——只要 1.76%。
  • 压缩是在算分之前做的：先把提问也折进这 512 维里，于是「打分」变成两个小矩阵相乘；算完再把结果展开回 128 维。
  • 挑专家分两道筛：256 个专家先按 8 组选出 4 组，再在这 4 组里挑 8 个；权重用原始分值归一化，不额外加偏置。

DeepEP deepseek-ai/DeepEP MoE 通信NVLink/RDMAJIT 内核
几百张显卡之间搬数据：同一个机箱直接抄内存，跨机箱才走网线。
  • 开多少个计算核、多少条网卡队列不是拍脑袋，是按带宽算出来的：直连模式 9 条，混合模式是核数 ×16+1。
  • 统计「谁到了」不用每个线程都加一次：专门留一个通知线程，用一条 64 位原子操作同时记计数和到达数，干活的线程不参与统计。
  • 同一个机箱内的卡，直接往对方内存里写（同一套地址）；跨机箱才先落到发送缓冲，再走网卡发出去。

DeepGEMM deepseek-ai/DeepGEMM FP8 GEMMJIT 编译SM100 内核
矩阵乘法加速库：不预先编译，用的时候现场生成一份只适合当前形状的代码。
  • 它不在发布时编死，而是运行时现场编：30 个参数（分块、流水级数、线程数、数据类型）一起焊进一份只跑这一种形状的机器码，跑起来只剩「启动」。
  • 流水几级不是调的，是算的：共享内存一共 232448 字节，能放几级就放几级；分块大小先被「显存列数 ≤512」卡掉一批。
  • 启动的线程块数正好等于 GPU 里的核数，每个块算完一块就自己去拿下一块，不用调度器派活。

smallpond deepseek-ai/smallpond 数据框架DuckDB3FS
海量数据框架：把大任务切成小的，丢到 3FS 上跑，算完就退。
  • 一个大作业被切成「生产任务」和「消费任务」两组：生产任务数按 worker 数和 CPU 数算出来；消费任务只合并不搬数据。
  • 没有常驻服务：一个调度进程用 mpirun 拉起一堆 worker，任务队列就是 3FS 上的一个目录，取任务靠「改名」——谁改名成功谁拿走。
  • 每个小任务开一个内存里的 DuckDB：读 Parquet、算完、写回 Parquet，进程就退。所以没有一堆常驻进程要养。

DeepSeek-OCR deepseek-ai/DeepSeek-OCR 多模态OCR视觉编码器
把一整页文档「看」成几百个小方块，再翻成文字，还告诉你每行字在哪。
  • 压缩发生在编码器里：一张 1024×1024 的图先切成 16 像素的小块，再两次减半，最后只剩 16×16=256 个 token。
  • 一页的「视觉开销」是固定的 273 个：16×16 的格子每行补一个换行、末尾补一个分隔符，正好 16×17+1。
  • 花多少 token 只看图片多大，不看字有多少：512 像素→64 个，1024→256 个，1280→400 个；位置则靠输出里的坐标标记还原。

TileKernels deepseek-ai/TileKernels TileLang算子库
把「按块搬数据、按块算」写成一种方言，再由编译器翻译成显卡指令——同一份写法能跑 NVIDIA 和昇腾。
  • 你只写开多少 block、每个 block 多少线程，搬运和计算都按块写（T.Kernel / T.copy / T.Parallel）。
  • 块多大、用几个线程是算出来的：小 batch 用 64 线程 × 32 元素，block_k 取与 hidden 的最大公约数。
  • 同一份写法换后端就能跑：探测到昇腾就换另一份 launcher，形状用 T.dynamic 留给运行时决定。
